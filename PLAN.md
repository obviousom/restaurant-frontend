# Frontend Build Plan (5 Phases)

Companion to the backend repo's `PLAN.md` and the cross-repo overview in
`restaurantmate/PLAN.md` at the workspace root. This file tracks only the
frontend's responsibilities in each phase.

## Phase 1 — Foundations & Auth
- Generate the Vite + React + TypeScript project inside this repo.
- Install and configure Tailwind CSS + shadcn/ui.
- Set up React Router (`src/routes`) and a base app shell/layout.
- `src/services`: axios client with JWT interceptor (attach/refresh
  token); TanStack Query provider.
- Login page + auth hook (`src/hooks/useAuth`); route guards per RBAC role.
- **Done when:** a user can log in against the Phase-1 backend, receive a
  JWT, and land on a protected placeholder dashboard route.

## Phase 2 — Core Operations
- Menu management UI (list/create/edit menu items & categories).
- Table/POS order-taking flow (select table → build order → submit).
- Kitchen display view (live-ish list of in-progress orders, status
  buttons).
- Billing/checkout screen (view bill, mark paid, download PDF from
  backend).
- **Done when:** a menu item can be ordered end-to-end through billing
  using only the UI.

## Phase 3 — Inventory & Purchasing
- Inventory dashboard (current stock levels, low-stock flags).
- Supplier CRUD screens.
- Purchase order creation/receiving UI.
- Recipe editor: map a menu item to ingredient quantities.
- **Done when:** stock changes from Phase 2/3 backend actions are visible
  in the inventory dashboard without a page-specific hack.

## Phase 4 — Background Jobs, Notifications & Reports
- Notification bell/center consuming the `notifications` API (polling or
  simple refetch interval via TanStack Query).
- Reports screen: trigger/download PDF and Excel reports from the
  `reports` API.
- **Done when:** notifications generated by backend scheduled jobs appear
  in the UI, and reports can be downloaded.

## Phase 5 — Dashboard, Testing & Polish
- Recharts dashboard: revenue, orders, sales, inventory, best-sellers,
  purchase trends, backed by `reports`/`sales` endpoints.
- Vitest + React Testing Library coverage for key components/hooks.
- Responsive/accessibility polish pass across all screens built in
  Phases 1–4.
- **Done when:** the dashboard renders real aggregated data, the test
  suite passes, and the app is usable on mobile widths.
